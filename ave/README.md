# RND на MiniGrid: итоговый статус

## 1. Что сделали

Реализовали **RND (Random Network Distillation)** по «Пути B» — упрощённо, без кастомной policy, поверх существующего baseline PPO (Stable-Baselines3). Идея: RND живёт в `gym.Wrapper`, добавляет `β·r_int` к внешней награде, SB3 учится как обычно, одной value-головой.

Добавлены файлы:

``` text
src/__init__.py
src/rnd/__init__.py
src/rnd/running_mean_std.py   # RunningMeanStd (Welford, state_dict/load_state_dict)
src/rnd/rnd_module.py         # RNDModule: target (frozen) + predictor (trainable)
src/rnd/wrapper.py            # IntrinsicRewardWrapper: r = r_ext + β·r_int
tests/test_rnd.py             # 4 unit-теста
pyproject.toml                # [tool.pytest.ini_options] pythonpath = ["."]
```

Изменены:

``` python
train.py     # RND_KEYS/RND_DEFAULTS, валидация, обёртка env, intrinsic_reward.txt,
             # best_model по r_ext, CLI (--map/--run-dir/--fixed-params/--device/--seed)
collect.py   # ACTIVE_MAPS (3 карты), RND_PARAMS, main(*, run_rnd, maps), CLI --rnd/--all-maps
```

`report.py` **не тронут** — таблица времени/успеха и графики `reward`/`steps_per_ep`/`fps` работают как раньше.

Ключевые технические решения:

- **Раскладка obs** — MiniGrid после `ImgObsWrapper` отдаёт **HWC** `(7, 7, 3)`, а не CHW. В `RNDModule` автоматическое определение (`obs_shape[-1] <= 16 and obs_shape[0] > 16`) и `np.transpose(arr, (2, 0, 1))`.
- **`_Encoder`** — устойчив к любому `H, W ≥ 1`: две свёртки `kernel=3, padding=1` → `AdaptiveAvgPool2d(1)` → `Flatten` → `Linear(channels, feature_dim)`. Работает на `5×5`, `7×7`, `11×11`, `16×16`.
- **Нормализация** — `obs_rms` (CHW) для входа target/predictor, `reward_rms` для `r_int`, `np.clip(normalized, -5, 5)` как защита от выброса.
- **`best_model` и остановка** — по **внешней** награде `r_ext` (сумма за эпизод), а не по `r_ext + β·r_int`. Иначе novelty-выброс в первом эпизоде «залипает».
- **Baseline не изменён** — при `use_rnd=False` все RND-ветки не активируются, поведение идентично исходному `train.py`.

## 3. Результаты (smoke 50k шагов, seed=42, CPU)

| Карта | Baseline (ver0) | RND (ver1, β=0.1) | Комментарий |
| --- | --- | --- | --- |
| **MultiRoom-N2-S4** | `100/100`, `107s` | `100/100`, `182s` | Контроль: оба решают, RND ×1.7 по времени |
| **KeyCorridorS3R3** | **`0/100`**, `97s` | **`100/100`**, `198s` | **Главный результат**: baseline не находит цель, RND решает |
| **DoorKey-5x5** | `7/100`, `101s` | `100/100`, `219s` | Подтверждает: RND решает, baseline почти нет |

**Главный тезис для отчёта:**

> На `KeyCorridorS3R3` (разреженная награда, 3 комнаты, ключ + дверь + шар) PPO без novelty за 50k шагов не находит цель ни разу (`0/100`), а PPO + RND (β=0.1) — `100/100`. Это воспроизводит ключевой тезис Burda et al. (2018): внутренняя награда за новизну критична в средах с разреженной внешней наградой.

**Контроль (MultiRoom):**

> На лёгкой `MultiRoom-N2-S4` оба метода дают `100/100` — RND не ломает обучение там, где внешней награды достаточно. Это подтверждает, что выигрыш RND на сложных картах — не артефакт, а следствие именно novelty.

**Цена:**

> RND добавляет ~1.7–2.2× по времени на CPU (wrapper + forward/backward RND каждый шаг). GPU-выигрыша не будет — узкое место среда (находка коллеги), RND только усугубляет.

## 4. Что получилось, что не очень

### Получилось

- **End-to-end RND пайплайн** — от wrapper'а до логов. Запускается, не падает, учится.
- **`rnd_loss` падает** в ~1800–3000 раз за 50k шагов (с `~0.008` до `~0.000003`) — predictor учится предсказывать target.
- **Главный результат воспроизведён**: RND решает `KeyCorridorS3R3` (`100/100`), baseline не решает (`0/100`).
- **Baseline не сломан** — поведение идентично исходному `train.py` (проверено по кривым).
- **Раскладка obs HWC** — выявлена и починена (была главная причина падений на старте).
- **`best_model` по `r_ext`** — фикс шага 2 применён, `best_model` не залипает на novelty-выбросе.

### Не очень / технический долг

1. **Фикс `RunningMeanStd.normalize` (шаг 1) не применён.** Сейчас первые ~30 шагов дают `r_int` до `5` (после клиппинга), из-за чего `reward.txt` эпизод 1 = `57` вместо `~1–10`, а `best_model` обновляется чуть позже, чем мог бы. **Успех `100/100` это не сломало** (RND всё равно помог), но:
   - в отчёте надо оговорить «на первых шагах `r_int` завышен, running std не набран»;
   - перед финальным `collect.py` фикс применить (2 строки в `running_mean_std.py`), перезапустить три RND-прогона.
2. **RND медленнее baseline в 1.7–2.2×** на CPU. Это цена wrapper'а + RND forward/backward. После фикса шага 1 разрыв должен сократиться (меньше выбросов → меньше итераций), но останется. В отчёт — как «цена RND».
3. **`intrinsic_reward.txt` не рисуется в `report.py`** — `CHARTS` не расширен. Не блокер, но в отчёт график `r_int`/`rnd_loss` придётся вставить вручную (или отдельным скриптом).
4. **Полный прогон `collect.py` ещё не делался** — только smoke по 3 картам, CPU, 50k. `collect.py` сейчас настроен на `1_000_000` шагов и `no_improve_episodes=500` — на CPU это часы. Перед финальным прогоном снизить до `200_000` / `500`.
5. **CLI `--fixed-params` в PowerShell** — JSON с одинарными кавычками ломается. Обходной путь: `python -c "from train import train; ..."` (использовали) или экранирование бэктиком. Для сокомандников — записать в README.
6. **`best_model` для KeyCorridor RND** — прогон остановился на 200-м эпизоде (кончились 50k шагов, `no_improve_episodes=1000` не сработал). `best_model.zip` есть, но если нужен «лучший по `r_ext`» — после фикса шага 1 и перезапуска он будет сохранён корректнее.

## 7. Оговорки для отчёта (готовые формулировки)

1. **Путь B**: «RND реализован по упрощённой схеме: одна value-голова PPO, `r = r_ext + β·r_int`, без раздельных GAE для ext/int. Это осознанное упрощение относительно Burda et al. (2018); абляция «две головы vs одна» — на неделе 3–4.»
2. **Нормализация `r_int`**: «`r_int` нормализуется running std и клиппируется в `[-5, 5]`. На первых шагах running std не набран, `r_int` завышен — в финальном прогоне устраняется ранним возвратом `normalize` при `count < 2` (фикс шага 1).»
3. **`best_model`**: «`best_model` выбирается по `r_ext` (сумма за эпизод), а не по `r_ext + β·r_int` — иначе novelty-выброс в первом эпизоде доминирует.»
4. **CPU vs GPU**: «На MiniGrid узкое место — среда, а не модель; GPU не даёт выигрыша (находка коллеги). RND только усугубляет разрыв (~1.7–2.2× на CPU), потому что добавляет forward/backward RND каждый шаг.»
5. **Предобучение на простой → сложной**: «Не реализуем — уводит от RND; возможное расширение в разделе "обсуждение".»
